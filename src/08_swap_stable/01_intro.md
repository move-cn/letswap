# 稳定币交换算法

## 本章目标

本章将深入讲解 Curve StableSwap 不变量的数学原理及其在 Sui Move 中的实现思路。学完本章后，你将理解：

- 稳定币交换为何需要专门的算法
- Curve StableSwap 不变量的数学推导
- 放大系数 A 对曲线形状和滑点的影响
- Newton 迭代法求解 D 的计算过程
- Move 合约中的核心函数设计
- StableSwap 与 Uniswap V3 稳定币池的对比

## 什么是稳定币

稳定币的通俗解释就是链上的美元，承诺链上的 1 个稳定币 Coin 可以和现实生活中的一美元一一兑换。比如常见的 USDC 和 USDT，它们的价格应该始终保持在 1 美元左右。

在 DeFi 中，经常需要在不同的稳定币之间进行交换，比如把 USDT 换成 USDC，或者把 DAI 换成 USDT。既然都是稳定币，它们之间的交换价格应该非常接近 1:1。比如 1 USDT 应该能换到大约 1 USDC，而不是 0.95 USDC。

稳定币之间的交换是 DeFi 中交易量最大的场景之一。因此，设计一种专门针对稳定币特性的交换算法具有重要的实际意义。

## 恒定乘积模型用于稳定币的问题

前面章节学过的 Uniswap V2 恒定乘积模型 `x * y = k`，对于稳定币之间的交换并不理想。用这个模型做稳定币交换，即使交换少量代币也会产生较大的价格偏移（滑点）。

举个例子：

- 池子里有 100 万 USDT 和 100 万 USDC
- 用 10 万 USDT 换 USDC
- 根据公式：(100 万 + 10 万) * y = 10000 亿
- y = 10000 亿 / 110 万 = 90.9 万
- 实际得到：100 万 - 90.9 万 = 9.1 万 USDC

你用 10 万 USDT 只换到 9.1 万 USDC，损失了 0.9 万，将近 9% 的滑点。

对于本应 1:1 兑换的稳定币来说，这个滑点是不可接受的。

根本原因是恒定乘积曲线的价格会随着交换量而偏离 1:1。它没有在 1:1 附近集中足够的流动性，导致任何交易都会推动价格移动。在价格-数量图上，恒定乘积曲线是一条双曲线，在 x = y 处的斜率不为零，这意味着即使是最小的交易也会改变价格。

## Curve 的 StableSwap 不变量

为了解决这个问题，Curve Finance 提出了 StableSwap 不变量。它的核心思路是：既然稳定币的价格总是接近 1:1，那为什么不设计一个专门在 1:1 附近集中流动性的公式呢？

StableSwap 可以理解为恒定乘积模型和恒定和模型的结合：

- **恒定和模型**：`x + y = 常数`，价格永远是 1:1，但一旦池子中一个币被耗尽就没有流动性了
- **恒定乘积模型**：`x * y = k`，价格会随交易变化，但永远不会耗尽流动性
- **StableSwap**：在大部分情况下接近恒定和（价格接近 1:1），在极端情况下退化为恒定乘积（保证不会耗尽）

StableSwap 曲线的形状像一个被拉平的椭圆：

- 在 x = y（即 1:1）附近，曲线几乎是直线，价格非常稳定
- 当池子严重不平衡时（比如一个币被大量换出），曲线会弯曲，价格开始偏离
- 即使极端情况，流动性也不会耗尽

用同样的例子来看：

- 池子里有 100 万 USDT 和 100 万 USDC
- 用 10 万 USDT 换 USDC
- 在 StableSwap 曲线下，由于 A 值的放大作用，你能换到大约 9.95 万以上的 USDC
- 滑点从 9% 降到了不到 0.5%

这就是为什么稳定币交换需要专门的算法。

## StableSwap 公式

以两个代币为例，StableSwap 不变量公式为：

```
A * (x + y) + x * y = D * A + (D / 2)^2
```

其中：

- `x` 是池中 CoinX 的数量
- `y` 是池中 CoinY 的数量
- `A` 是放大系数（Amplification Coefficient），控制曲线在 1:1 附近有多"平"
- `D` 是池中两种代币在平衡状态下的总和（当 x = y 时，x = y = D/2）

该公式有两个极端情况：

- 当 `A = 0` 时，公式退化为 `x * y = (D/2)^2`，即恒定乘积模型
- 当 `A` 趋向无穷大时，公式趋近 `x + y = D`，即恒定和模型

`A` 越大，曲线在 1:1 附近越平坦，意味着更大的交易量也不会导致价格偏离。

更一般地，对于 N 个代币的 StableSwap 公式可以推广为：

```
A * sum(xi)^N + prod(xi) = A * D^N + (D / N)^N
```

其中 xi 是第 i 个代币的数量，N 是代币数量。本书聚焦于双币池的情况，即 N = 2。

## StableSwap 的 Move 实现思路

在 Sui Move 中实现 StableSwap，核心在于求解 D 值和计算 swap 输出量。下面介绍关键的函数签名和计算逻辑。

### 核心函数签名

```
// 计算 StableSwap 的输出数量
public fun get_amount_out_stable(
    x_in: u64,          // 输入代币数量
    x_reserve: u64,     // 池中输入代币的储备量
    y_reserve: u64,     // 池中输出代币的储备量
    amp: u64,           // 放大系数 A（放大后的整数值，如 A * 100）
    fee_bps: u64,       // 手续费（基点）
): u64;

// 根据当前储备量求解 D
fun compute_d(
    x: u64,             // CoinX 储备量
    y: u64,             // CoinY 储备量
    amp: u64,           // 放大系数 A
): u64;

// 已知 D 和一个代币的数量，求解另一个代币的数量
fun compute_y(
    x: u64,             // 已知的 CoinX 数量
    d: u64,             // 当前的 D 值
    amp: u64,           // 放大系数 A
): u64;
```

### 放大系数 A 的作用

放大系数 A 是 StableSwap 的核心参数，它决定了曲线在 1:1 附近的平坦程度。在合约实现中，A 通常以放大后的整数存储，比如 `A = 100` 表示实际值为 100，`A = 10000` 表示实际值为 100。

A 的作用可以用一个直观比喻来理解：A 就像是连接恒定和曲线和恒定乘积曲线的弹簧。A 越大，弹簧把曲线拉向恒定和（更平），A 越小，弹簧放松，曲线回归恒定乘积（更弯）。

### Newton 迭代法求解 D

已知 x、y 和 A，求解 D 是 StableSwap 的核心计算。由于 D 没有解析解，需要使用 Newton-Raphson 迭代法求解。

将公式重写为关于 D 的方程：

```
f(D) = A * (x + y) + x * y - A * D - (D/2)^2 = 0
```

Newton 迭代法的更新公式为：

```
D_{n+1} = D_n - f(D_n) / f'(D_n)
```

伪代码如下：

```
fun compute_d(x, y, amp) {
    // 初始猜测值：取 x + y 的简单平均
    let d = x + y;

    // 迭代最多 256 次
    for (i = 0; i < 256; i = i + 1) {
        let d_prev = d;

    // 计算 f(D) = A * (x + y) + x * y - A * D - (D/2)^2
    // 计算 f'(D) = -A - D/2
    // Newton 更新：D = D - f(D) / f'(D)

    let sum_xy = x + y;
    let product_xy = x * y;
    let d_half = d / 2;

    // 分子：A * sum_xy + product_xy - A * d - d_half * d_half
    let numerator = amp * sum_xy + product_xy - amp * d - d_half * d_half;

    // 分母：A + d_half（取绝对值的负数）
    let denominator = amp + d_half;

    // 更新 D（注意符号处理）
    d = d + numerator / denominator;

    // 收敛判断：如果变化量小于精度阈值，停止迭代
    let diff = d_prev - d;
    if (diff < 1 && diff > -1) {
        break;
    }
    }

    d
}
```

实际实现中需要注意以下几点：

- 所有运算使用整数，需要合理选择精度放大倍数（如 10^10）
- 迭代的收敛速度很快，通常 10 次以内即可达到精度要求
- 需要设置最大迭代次数防止无限循环
- 每次迭代的中间结果可能为负数，需要用有符号整数处理

已知 D 求解 y（即 `compute_y`）的逻辑类似，同样使用 Newton 迭代法，此处不再赘述。

### Swap 计算的伪代码

有了 `compute_d` 和 `compute_y` 之后，swap 的输出量计算就很简单了：

```
fun get_amount_out_stable(x_in, x_reserve, y_reserve, amp, fee_bps) {
    // 1. 扣除手续费
    let fee = x_in * fee_bps / 10000;
    let x_in_after_fee = x_in - fee;

    // 2. 计算当前 D 值
    let d = compute_d(x_reserve, y_reserve, amp);

    // 3. 新的 x 储备量（加上输入）
    let new_x = x_reserve + x_in_after_fee;

    // 4. 根据新的 x 和 D，计算新的 y 值
    let new_y = compute_y(new_x, d, amp);

    // 5. 输出量 = 旧 y - 新 y
    let amount_out = y_reserve - new_y;

    amount_out
}
```

这个流程体现了 StableSwap 与恒定乘积模型的本质区别：恒定乘积直接用 `y = k / x` 计算，而 StableSwap 需要先求解 D 再求解 y，多了一步迭代计算。这就是 StableSwap 在 Gas 消耗上高于恒定乘积模型的原因。

## A 参数选择的影响

放大系数 A 的选择直接影响稳定币交换的滑点表现。下面用数值示例说明不同 A 值的影响。

假设池中有 100 万 CoinA 和 100 万 CoinB（初始平衡状态），使用 10 万 CoinA 交换 CoinB：

| A 值   | 可换出的 CoinB | 滑点     | 特点                   |
|--------|---------------|---------|-----------------------|
| 0      | 9.09 万       | 9.1%    | 退化为恒定乘积，滑点最大 |
| 10     | 9.60 万       | 4.0%    | 有一定集中效果          |
| 100    | 9.85 万       | 1.5%    | 较好的稳定币交换体验     |
| 1000   | 9.95 万       | 0.5%    | 非常平坦，适合主流稳定币 |
| 10000  | 9.99 万       | 0.1%    | 极度平坦，但极端风险高   |

可以看到，A 值越大，滑点越低。但 A 值并非越大越好。当 A 值极大时，曲线几乎是一条直线，这意味着一旦价格偏离 1:1，套利者几乎无法通过 swap 推动价格回归。如果某个稳定币真的脱锚，过大的 A 值会导致池子中的流动性在错误的价格上被迅速消耗。

Curve 在实际部署中，主流稳定币池（如 3pool）的 A 值通常在 100 到 1000 之间，这是一个在低滑点和安全性之间的平衡。

## Curve StableSwap 与 Uniswap V3 稳定币池对比

两种方案都能实现稳定币的低滑点交换，但设计思路完全不同：

| 对比项         | Curve StableSwap          | Uniswap V3 稳定币池         |
|--------------|---------------------------|----------------------------|
| 核心思路      | 数学公式内置价格粘性       | LP 手动集中流动性到窄区间    |
| LP 操作复杂度 | 简单，存入即可             | 需要选择精确的价格区间       |
| 滑点控制      | 由 A 参数自动保证          | 由 LP 的区间宽度决定         |
| 资金效率      | 高，公式自动集中           | 更高，但依赖 LP 的主动管理   |
| 脱锚风险应对  | A 参数可调整               | LP 可手动调整区间            |
| Gas 消耗      | 较高（Newton 迭代）        | 中等（Tick 计算）           |
| 合约复杂度    | 中等（数学计算）           | 高（Tick 系统）             |

Curve Finance 是最早采用 StableSwap 不变量的去中心化交易所，专注于稳定币之间的交换。它目前是 DeFi 中稳定币交易量最大的平台之一。Curve 后来也扩展到了非稳定币资产（比如 ETH/stETH），但其核心优势仍然在稳定币领域。

Uniswap V3 通过集中流动性来解决稳定币交换的问题。LP 可以把流动性集中在 0.999 - 1.001 这样极窄的价格区间内，实现和 StableSwap 类似的效果。Uniswap V3 的稳定币池（如 USDC/USDT）也是目前交易量很大的池子。

在 Sui Move 生态中，可以根据实际需求选择实现方案。如果专注于稳定币交易，StableSwap 的实现更简单直接；如果需要通用的交易框架同时支持稳定币，V3 的集中流动性方案更具扩展性。

## 本章小结

本章详细讲解了 Curve StableSwap 不变量的数学原理与 Move 实现思路。要点如下：

- 恒定乘积模型 `x * y = k` 用于稳定币交换时滑点过高，需要专门的设计
- StableSwap 不变量 `A * (x + y) + x * y = D * A + (D/2)^2` 在 1:1 附近集中流动性，将滑点从约 9% 降至不到 0.5%
- 放大系数 A 控制曲线平坦程度，A 越大滑点越低，但脱锚风险也越高
- 核心计算依赖 Newton-Raphson 迭代法求解 D 值，通常 10 次以内收敛
- Move 实现需要三个核心函数：`compute_d`、`compute_y`、`get_amount_out_stable`
- 与 Uniswap V3 的集中流动性方案相比，StableSwap 通过数学公式自动实现价格粘性，LP 操作更简单

StableSwap 是 DeFi 中针对稳定币交易的关键优化。理解它的数学原理和实现方法，有助于在设计稳定币交易池时做出合理的技术选择。
