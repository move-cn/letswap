# 什么是 DeFi

## 去中心化金融的定义

DeFi 是"去中心化金融"（Decentralized Finance）的缩写，也常被称为"开放式金融"（Open Finance）。它指的是构建在区块链之上、以智能合约为核心载体的一类金融服务体系。与传统金融不同，DeFi 不依赖银行、券商、交易所等中介机构，而是通过部署在链上的程序代码来自动执行借贷、交易、支付、保险等金融业务。

通俗地说，如果传统金融是一家有营业时间、有柜员、有审批流程的银行，那么 DeFi 就是一台永不打烊、无需审批、代码即规则的自助金融终端。任何人只需要一个区块链钱包和网络连接，就可以随时使用这些金融服务。

## DeFi 的发展历程

DeFi 并非凭空出现，它的发展经历了数个关键节点：

**2017 年 -- 萌芽期**

MakerDAO 在以太坊上推出，它是第一个去中心化稳定币协议，允许用户通过抵押以太坊（ETH）来生成与美元锚定的稳定币 DAI。MakerDAO 的上线标志着 DeFi 的起点，它证明了去中心化借贷和稳定币发行的可行性。

**2018-2019 年 -- 基础设施建设期**

这一阶段涌现了一批奠定 DeFi 基础的协议：Uniswap（去中心化交易所）、Compound（去中心化借贷）、Synthetix（合成资产）等先后上线。这些协议各自解决了不同的金融需求，并开始形成可组合的生态系统。

**2020 年 -- DeFi Summer（DeFi 之夏）**

2020 年夏天，Compound 协议推出了流动性挖矿（Liquidity Mining）机制，向用户提供代币激励。这一模式迅速被其他协议效仿，大量资金涌入 DeFi 市场。DeFi 锁仓总价值（TVL）从不足 10 亿美元飙升至超过 150 亿美元。这一时期被称为"DeFi 之夏"，是 DeFi 发展史上最具爆发力的阶段。

**2021 年至今 -- 成熟与扩展期**

DeFi 协议不断迭代升级，Uniswap 推出 V3 集中流动性模型，Layer 2 扩容方案降低交易成本，跨链桥将 DeFi 扩展到多条区块链。同时，DeFi 的监管合规也开始受到各国政府的关注。截至 2024 年底，DeFi 的锁仓总价值已达到数百亿美元量级，涵盖了交易、借贷、衍生品、保险等多个细分领域。

## TVL -- 衡量 DeFi 规模的核心指标

TVL（Total Value Locked，锁仓总价值）是衡量 DeFi 协议规模的最常用指标。它表示用户存入某个 DeFi 协议中的资产总价值，通常以美元计价。TVL 越高，说明该协议中锁定的资金越多，用户对其信任度也越高。

TVL 的计算方式很简单：将协议中所有锁定的代币数量乘以各代币的当前市场价格，再求和。需要注意的是，TVL 并不完全等同于协议的收入或利润，它反映的是资金的规模。

## DeFi 的主要类别

DeFi 的生态非常丰富，以下是几个最主要的类别：

| 类别 | 说明 | 代表协议 |
|------|------|----------|
| DEX（去中心化交易所） | 用户直接在链上交换不同的代币，无需中心化撮合方 | Uniswap、Curve、Cetus |
| Lending（借贷） | 用户存入资产获取利息，或抵押资产借出其他资产 | Aave、Compound |
| Stablecoin（稳定币） | 与法币或其他资产锚定的代币，用于降低波动性 | DAI、USDC、USDT |
| Derivatives（衍生品） | 链上的期货、期权、合成资产等 | dYdX、Synthetix |
| Yield（收益聚合） | 自动化策略，帮助用户在不同协议间优化收益 | Yearn Finance |

在本书中，我们将聚焦于 DEX（去中心化交易所）中的 Swap（代币交换）功能，这是 DeFi 中最基础也最核心的应用之一。

# 为什么选择 Sui

要构建 DeFi 应用，需要选择一个合适的区块链平台。在众多公链中，我们选择 Sui 作为本书的教学平台。在解释原因之前，先通过一张对比表来了解 Sui 与其他主流平台的关键差异：

| 特性 | Ethereum（以太坊） | Solana | Sui |
|------|--------------------|--------|-----|
| 共识机制 | PoS（权益证明） | PoH + PoS | Narwhal + Bullshark |
| 编程语言 | Solidity | Rust | Move |
| 理论 TPS | 约 15-30 | 约 65,000 | 约 120,000+ |
| 交易确认时间 | 约 12 秒 | 约 0.4 秒 | 约 0.5 秒（拜占庭一致） |
| 平均 Gas 费用 | 较高（数美元） | 极低（小于 0.01 美元） | 极低（小于 0.01 美元） |
| 数据模型 | 账户模型 | 账户模型 | 对象模型 |
| 并行执行 | 不支持 | 支持（需声明依赖） | 支持（天然并行） |

从上表可以看出，Sui 在吞吐量、交易确认速度和 Gas 费用方面都有显著优势。这些特性对于 DeFi 应用尤为重要 -- 高 TPS 意味着在市场波动剧烈时也能顺畅交易，低 Gas 费用降低了用户的使用门槛，快速的确认时间减少了交易中的滑点和不确定性。

## Sui 的核心特性

### 对象模型

Sui 与以太坊、Solana 最根本的区别在于数据模型。以太坊使用"账户模型"，每个地址有一个余额状态，所有状态变更需要按顺序处理。Sui 则使用"对象模型"（Object Model）。

在 Sui 中，一切数据都以"对象"（Object）的形式存在。每个对象都有唯一的 ID、所属者和版本号。一个 Coin 是一个对象，一个 NFT 是一个对象，一个流动性池也是一个对象。这种设计带来两个关键优势：

1. **清晰的所有权关系**：每个对象都有明确的拥有者，可以是某个地址、某个其他对象，或者是共享状态。这使得资产的管理和权限控制变得非常直观。
2. **天然的并行处理能力**：如果两个交易操作的是不同的对象，它们之间没有依赖关系，可以同时并行执行，不需要排队等待。

### 并行执行

并行执行（Parallel Execution）是 Sui 高性能的核心秘诀。在以太坊上，所有交易必须按顺序逐一处理，即使这些交易彼此毫无关联。Sui 则通过对象模型自动识别交易之间的依赖关系 -- 如果交易 A 操作对象 X，交易 B 操作对象 Y，且 X 和 Y 不同，那么 A 和 B 可以同时执行。

对于 DeFi 场景来说，这意味着：当用户甲在交换 SUI/USDC，用户乙在交换 ETH/BNB 时，这两笔交易可以并行处理，互不阻塞。只有在两个用户同时操作同一个流动性池时，才需要按顺序执行。这种设计使得 Sui 在实际负载下能够达到远高于传统链的吞吐量。

### 低 Gas 费用

得益于高效的共识算法和并行执行能力，Sui 的 Gas 费用维持在极低水平。即使在网络繁忙时，单笔交易的 Gas 费用通常也远低于 0.01 美元。对于需要频繁交互的 DeFi 应用（如套利、多次小额交换等），低 Gas 费用意味着用户不必为操作成本所困扰。

# 什么是 Move

## Move 的起源

Move 编程语言最初由 Facebook（现 Meta）为其 Diem（原名 Libra）区块链项目开发。Diem 项目的目标是在全球范围内构建一个合规的数字货币支付系统，而现有的智能合约语言（如 Solidity）在安全性和资产表示能力上无法满足其要求，因此团队决定从零设计一门新的语言。

虽然 Diem 项目最终因监管原因未能上线，但 Move 语言的核心思想得以保留。Sui 的开发团队（Mysten Labs）中有多位来自 Diem 项目的核心成员，他们将 Move 的设计理念带到了 Sui，并在此基础上进行了大量扩展和优化。

## 面向资源的设计

Move 最显著的特点是"面向资源"（Resource-Oriented）的编程范式。在传统智能合约语言中，代币通常用一个数字（整数）来表示余额，资产的安全性完全依赖于合约代码的正确性。而在 Move 中，资产本身就是一种"资源"（Resource），具有以下特性：

- **不可复制**：一个 Coin 资源不能被随意复制。这从根本上杜绝了"双花"（Double Spend）问题。
- **不可丢弃**：一个资源一旦被创建，就必须被明确地使用或转移，不能被意外丢弃。这防止了资产因编程错误而被永久丢失。
- **可存储**：资源可以被存储在对象中，作为对象的字段存在。

这种设计将资产安全从"依赖代码逻辑"提升到了"语言层面保障"的高度。即使开发者犯了某些编程错误，Move 的类型系统也能在编译阶段就捕获这些问题，而不是等到运行时才暴露。

## 能力系统（Ability System）

Move 使用"能力"（Ability）来控制类型的行为。每个结构体可以声明零到多种能力，这些能力决定了该类型的值能做什么操作。Move 提供四种基本能力：

| 能力 | 关键字 | 说明 |
|------|--------|------|
| 复制 | `copy` | 允许该类型的值被复制。适用于不需要稀缺性的数据，如配置信息。 |
| 丢弃 | `drop` | 允许该类型的值被丢弃（不在使用时自动清理）。适用于临时数据。 |
| 存储 | `store` | 允许该类型的值被存储在对象内部或作为全局状态的一部分。 |
| 键 | `key` | 允许该类型作为一个全局存储的对象（拥有 UID 字段）。 |

一个 Coin 通常只需要 `key` 和 `store` 能力 -- 它有 `key` 所以可以作为一个独立的对象存在，有 `store` 所以可以被存储在其他对象中。注意它没有 `copy`，这意味着 Coin 不能被复制，从语言层面保证了资产不会被凭空增发。

下面是一个简单的 Coin 类型声明示例：

```move
public struct MyCoin has key, store {
    id: UID,
    balance: Balance,
}
```

而一个事件（Event）结构体通常需要 `copy` 和 `drop` 能力，因为事件只是一种通知信息，可以复制，也可以在使用后被丢弃：

```move
public struct SwapEvent has copy, drop {
    coin_in_type: String,
    coin_out_type: String,
    amount_in: u64,
    amount_out: u64,
}
```

通过灵活组合这四种能力，开发者可以精确控制每种数据类型的行为，在安全性和灵活性之间找到最佳平衡。

## 安全性保障

Move 在安全性方面做了多层防护：

- **模块化与封装**：Move 的模块（Module）系统支持严格的封装。结构体的字段默认对外部模块不可见，只有定义该结构体的模块才能访问其内部字段。这意味着 Coin 的余额字段不会被外部代码随意篡改。
- **字节码验证**：Move 代码编译为字节码后，在部署前会经过严格的验证器（Verifier）检查，确保类型安全、资源安全、引用安全等约束全部满足。
- **无重入攻击**：Move 不支持动态调用（类似于 Solidity 中的 `call`），从根本上消除了重入攻击的风险。

# Sui + Move：构建 DeFi 的理想组合

将 Sui 的高性能平台与 Move 的安全语言结合，为 DeFi 开发提供了独特的优势：

**资产安全有语言层面的保障。** Move 的资源模型和能力系统确保代币不会被复制、丢失或意外篡改。在 DeFi 中，资金安全是第一要务，Move 从语言设计上就为这一需求提供了坚实基础。

**对象模型天然适合 DeFi。** Sui 的对象模型使得流动性池、代币、交易订单等 DeFi 核心概念可以用独立的对象来表示，所有权关系清晰，操作权限明确。比如一个流动性池可以是一个共享对象（Shared Object），任何用户都可以向其发送交易；而用户的 LP Token 则是用户私人拥有的对象，只有持有者才能操作。

**并行执行提升吞吐量。** 当 DeFi 应用的用户量增长时，Sui 的并行执行能力使得不同的交易对可以独立处理，不会因为某几个热门交易对的拥堵而拖慢整个系统。

**低 Gas 费用降低门槛。** 极低的交易成本使得小额交易和频繁操作变得可行，这对于 DeFi 的普及至关重要。用户不必担心 Gas 费用超过交易收益。

在接下来的章节中，我们将利用 Sui 和 Move 来逐步构建一个完整的 Swap 系统。从最简单的固定汇率交换，到 Uniswap V2 的恒定乘积模型，再到更高级的订单簿和集中流动性模型，你将亲身体验到 Sui + Move 在 DeFi 开发中的强大能力。

# 本节小结

本节介绍了 DeFi、Sui、Move 三个核心概念及其相互关系：

- DeFi 是构建在区块链上的去中心化金融服务体系，经历了从 2017 年 MakerDAO 萌芽到 2020 年 DeFi Summer 爆发的发展过程，TVL 是衡量其规模的核心指标
- Sui 是一个高性能区块链平台，核心特性包括对象模型、并行执行和低 Gas 费用，在 TPS、确认速度和成本方面相比以太坊有显著优势
- Move 是一门面向资源的智能合约语言，起源于 Diem 项目，通过能力系统（key、store、drop、copy）在语言层面保障资产安全
- Sui + Move 的组合为 DeFi 开发提供了安全、高效、低成本的技术基础，是构建去中心化金融应用的理想选择
